## Regra geral — normalização de espaços

Não é uma entrada de tabela: é uma regra no fim do postfix, que vale para **todo**
texto localizado (skills, status, itens, dicas). Entra por último de propósito — as
chaves das tabelas casam com o texto ORIGINAL, com os espaços duplos inclusos.

| antes | depois | fonte |
|---|---|---|
| qualquer texto com dois espaços seguidos | um espaço só | **Medição no próprio jogo**: `". "` aparece **116** vezes contra **77** de `".  "` — a maioria é um espaço, então os duplos são minoria. Cobre 72 skills e também itens/status/dicas, que o censo não lista. |

> Espaço **no fim** do texto ficou de fora de propósito: é invisível no tooltip e aparar poderia colar palavras se o jogo concatenar strings (decisão registrada como `RV-8b-2d`).

## Que fontes entram neste livro

| tipo de fonte | como foi usada |
|---|---|
| **O próprio asset do jogo** (via `docs/cobertura/*.csv`) | é o texto ORIGINAL que a coluna *antes* mostra — casar contra ele é o que garante que a chave dispara |
| **O código do jogo** (`Assembly-CSharp.dll`, decompilado) | quando a tooltip afirma mecânica ou número: é a fonte que **vence em divergência** |
| **O texto do próprio jogo para o status** | confirma número que não está no caster (ex.: `Patient Hunter`, "Range increased by 1 per stack") |
| **Medição no jogo** (`tools/audit_tooltips.py`) | decidiu o padrão de espaço (116 × 77), levantou as famílias de redação divergentes e achou os 9 defeitos de grafia |
| **Wiki (Fandom)** | segunda opinião — **parou na v.19** e perdeu para o código em 3 casos no lote Ranger |
| **Patch notes datados** (SteamDB) | a versão mais recente é a verdade; usados para checar mudanças posteriores à v.19 |

## Como conferir se um ajuste foi aplicado

1. `python tools/check_fix_keys.py` — a chave existe no texto do jogo? Chave que não existe **nunca dispara, e falha em silêncio**.

2. Abrir a tooltip no jogo. O mod escreve no log toda vez que muda algo
   (`LogOutput.log`, linhas `Better Tooltips:`), então o log é a prova.
